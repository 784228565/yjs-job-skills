# 队列文件读取说明

> ⚠️ WorkBuddy 环境直接用 `find_applicable.py`（工作目录 `C:\Users\78422\Desktop\工作agent`），它自动找最新队列并筛选可投递岗位。无需手动调用 `config.find_latest_queue_file()`。

## 文件位置

队列目录：`C:\Users\78422\Desktop\工作agent\筛选agent\`（由 `config.QUEUE_DIR` 决定，可用环境变量 `JD_QUEUE_DIR` 覆盖）

文件名包含日期（如 `队列2026-07-22.xlsx`）。**不要写死某个日期**，按以下规则定位：
1. 优先读取**当天日期**的队列文件。
2. 没有当天文件时，读取**修改时间最新**的 `队列*.xlsx`。
3. 忽略 `~$` 开头的 Excel 临时锁文件。

推荐直接用 `config.find_latest_queue_file()` 自动完成上述定位。

## 读取方式

使用 Python openpyxl 读取：

```python
import sys; sys.path.insert(0, r"C:\Users\78422\.codex\skills\job-delivery\scripts")
import config
import openpyxl

queue_path = config.find_latest_queue_file()
if queue_path is None:
    raise FileNotFoundError("未找到任何 队列*.xlsx")
wb = openpyxl.load_workbook(queue_path)
ws = wb["投递队列"]
```

## 工作表结构

读取【投递队列】工作表中的数据，按「序号/排名」列升序排列处理（该列缺失时用数据行号从第1个数据行起生成序号）。

> 列名兼容说明：实际队列文件（筛选 agent 产出）使用的列名与早期版本不同，但含义一致。
> 下表列出**规范字段**及其**可接受的列名（任一即可）**，读取时按"先规范名、后别名"匹配，不再要求固定列名。

### 预期列（按列名识别，支持别名）

| 规范字段 | 可接受的列名（任一即可） | 说明 | 必填 |
|----------|--------------------------|------|------|
| 序号 | 序号、排名 | 投递顺序编号（排名即行序；两列皆无则用数据行号生成） | 是 |
| 岗位名称 | 岗位名称 | 岗位标题 | 是 |
| 公司名称 | 公司名称、公司 | 公司名称 | 是 |
| 投递链接 | 投递链接、投递地址 | 岗位URL | 是 |
| 平台 | 平台 | 招聘平台名称（LinkedIn/Boss直聘/51job等） | 否 |
| 薪资 | 薪资 | 薪资范围 | 否 |
| 地点 | 地点 | 工作地点 | 否 |
| 备注 | 备注 | 其他备注 | 否 |

### 错误处理

- 文件不存在 -> 记录阻断性问题，停止执行
- 工作表【投递队列】不存在 -> 记录阻断性问题，列出可用工作表，停止执行
- 缺少"序号/排名"任一列名且无可用行号 -> 记录阻断性问题，停止执行
- 缺少"岗位名称"列 -> 记录阻断性问题，停止执行
- 缺少"公司名称/公司"任一列名 -> 记录阻断性问题，停止执行
- 缺少"投递链接/投递地址"任一列名 -> 记录阻断性问题，停止执行
- 某行缺少投递链接 -> 标记该行为跳过，记录非阻断性问题

### 跳过标记

读取到以下标记的行跳过不处理：
- 投递链接为空或"-"
- 任何列包含"重复"、"已投"、"已投递"、"duplicate"等标记
